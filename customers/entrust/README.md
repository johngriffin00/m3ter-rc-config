# Entrust

Identity-verification checks (Document Check: Flash / Boost / Sherlock, per check, per
region), sold through Revenue Cloud and metered and rated in m3ter.

**The loop:** quote → order → activate (Revenue Cloud) → `ordersync` → account, bespoke plan,
negotiated pricings, account plan (m3ter) → usage, bill (m3ter) → `billsync` → liable
summaries (Revenue Cloud) → Generate Invoices.

| Folder | What | Arrives in |
| --- | --- | --- |
| `revenue-cloud/` | the Document Check catalog as rc-config JSON, generated by `build_config.py` | phase 4 |
| `m3ter/` | the m3ter product / meters / plan template config | phase 4 |
| `m3sh/` | the m3sh Order Handler and Usage Data workflow exports and DSL | phase 4 |
| `snapshots/` | order `00000102`, Acme's bill, m3ter org dumps | phase 3–4 |
| `analysis/` | catalog and quoting recommendations, m3ter → Revenue Cloud mapping rationale, quote reconstructions | phase 4 |
| `docs/` | the documentation set (`index.html` is the contents page) | phase 4 |
| `DECISIONS.md` | every open question in one place | now |

Until the move, these live in `revenue-cloud-config/{config,documents,models}/…entrust…`
and `m3ter-config/{json,workflows}/entrust/`.
