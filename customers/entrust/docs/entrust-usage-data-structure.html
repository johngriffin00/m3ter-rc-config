m3sh workflows · Entrust · m3ter Bill → Salesforce Revenue Cloud

Entrust Usage Data Sync

How the four exported m3sh workflows turn one m3ter bill into Revenue Cloud's usage chain — UsageSummary, UsageRatableSummary and UsageBillingPeriodItem — one entry point and three sub-workflows that share its state. Every step below is read from the JSON exports in json/entrust/m3sh/; the Python handler that feeds the trigger is on_bill_change, the pre-m3sh script.

Call graph

Four phases, one bill

Phase 0 · outside m3sh

Python nets the bill

  • Webhook billing.bill.created / updated → on_bill_change reads the Bill and its USAGE line items only.
  • apply_grants reduces quantity by matching quantity Balances; apply_commitments draws the remainder down against TOK / USD Balances via the rate.
  • Posts accountId, bill dates and one entry per line with ConsumptionUnits, OverageUnits, NetUnitRate, OverageQuantity, TierQuantity, TotalAmount, OverageAmount, TotalUsedQuantity, CurrencyIsoCode, RatingDecisionDateTime, accountPlanId.
Phase 1

Account and per-line context

  • External mapping m3ter Account → salesforceAccountId (TRUE exit only).
  • Per line: load the m3ter AccountPlan; its custom fields TUEId, AssetId, EntitlemntUomId are the Salesforce ids.
  • SOQL the child bucket (Parent.Type = 'UsageEntitlementBucket') for that TUE and UoM → UEBid, UoMid.
Phase 2

Three objects, find-or-create

  • UsageSummary is searched by Account + Asset + Start + End + bucket; sets isUsageSummaryNew.
  • UsageRatableSummary and UBPI are reached through sfUsageSummary.RatableSummaryId / LiableSummaryId: null → create, else read and update.
  • Every update strips Status first so an existing record is never reset to New.
Phase 3

Back-links and bucket

  • If the summary was new: write RatableSummaryId and LiableSummaryId onto it.
  • Read the child bucket and overwrite BucketBalance with TotalUsedQuantity, ConsumedEntitlement with ConsumptionUnits.
  • Next line item.

What to settle before writing billsync

  1. The netting never lived in m3sh. ConsumptionUnits, OverageUnits, TotalAmount and friends arrive already netted by apply_grants / apply_commitments in the Python handler. The port holds both halves; the Balance netting becomes a brick between resolve and build, and until the commitment lands as a m3ter Balance it is a pass-through.
  2. The two halves disagree about ConsumptionUnits. Python posts ConsumptionUnits = quantity (the total) and OverageUnits = final. The workflow then writes DebitedUnits = ConsumptionUnits and ConsumptionUnits = ConsumptionUnits + OverageUnits — which is right only if the posted value was the debited portion. One of them is wrong; define it once in the port: total = quantity, overage from the priced bands, debited = total − overage.
  3. State bleeds across the loop. The UsageSummary create path sets isUsageSummaryNew but never resets sfUsageSummary. For the second line of a run, if the first line found an existing summary, the ratable and UBPI sub-workflows test the previous line's RatableSummaryId / LiableSummaryId and update the wrong records. The Python version keys every object per line explicitly.
  4. Per-line keys ride on AccountPlan custom fields (TUEId, AssetId, EntitlemntUomId) — one AccountPlan per usage resource. Entrust's Document Check has six TUEs on one AccountPlan, so this cannot carry over. The order sync already leaves the per-resource key on the Pricing (pricing_<TUE Id> and the Salesforce/TransactionUsageEntitlement external mapping); the bill line item's pricingId is the join.
  5. Which bucket is answered: the child, Parent.Type = 'UsageEntitlementBucket', filtered by TUE and UoM. Read BucketBalanceUomId off the result instead of filtering on it.
  6. Idempotency is the natural key, Status only on insert. UsageSummary is found by Account + Asset + StartDateTime + EndDateTime + bucket; the other two are reached through the back-links; every update removes Status from the payload. Same rule for the port — and a UBPI-only first pass keys on bucket + period directly.
  7. EndDateTime is shaved by one second for the two summaries but not the UBPI. The posted end is m3ter's exclusive midnight; the summaries get 23:59:59, the UBPI gets 00:00:00 of the next day. Pick one — Revenue Cloud's own TUE and bucket end dates are 23:59:59.
  8. Date arithmetic assumes the m3ter ISO shape. String.left(x, 22) + "Z" keeps two decimal places of 2026-11-14T00:00:00.000Z before subtracting; any other input format breaks it. In Python this is a parse and timedelta(seconds=1).
  9. The bucket balance is overwritten by hand. BucketBalance = TotalUsedQuantity and ConsumedEntitlement = ConsumptionUnits on the child bucket, every run, so Revenue Cloud's own drawdown is bypassed. Acme's buckets are zero-entitlement; make this an optional, off-by-default brick.
  10. Only USAGE lines are posted — the Python filter is what keeps STANDING_CHARGE, BALANCE_FEE and BALANCE_CONSUMED out. Keep it: the order line price is billed by Revenue Cloud itself.
  11. Silent exits. The Account mapping check has no FALSE branch, the UEB query is a single-object read that is not checked for a hit, and several matches for a UsageSummary are looped so the last wins. Decide whether the port logs or raises.
  12. Cosmetic. The UBPI create path's last step is titled “Set sfUsageRatableSummaryId” but sets the UBPI id; CurrencyIsoCode is a static USD in Python rather than the line item's currency.

Reference: payload, objects and fixed ids

Trigger payload (from on_bill_change)

  • accountId, accountCode, billDate, startDate, endDate, currency
  • lineitems[]: Description, accountPlanId, StartDateTime, EndDateTime, Unit, DebitedUnits, ConsumptionUnits, OverageUnits, RatingDecisionDateTime, NetUnitRate, OverageQuantity, TierQuantity, TotalAmount, OverageAmount, TotalUsedQuantity, CurrencyIsoCode
  • USAGE line items only; posted with HTTP basic auth to the m3sh webhook URL

Salesforce objects

  • Read: UsageEntitlementBucket (SOQL, child level), UsageSummary (SOQL + read), UsageBillingPeriodItem (read)
  • Written: UsageSummary, UsageRatableSummary, UsageBillingPeriodItem, UsageEntitlementBucket
  • API version 65.0, OAuth client credentials (the loader is pinned to 66.0)

m3ter entities and custom fields relied on

  • External mapping m3ter Account → Salesforce (reverse lookup by m3ter id)
  • AccountPlan.customFields.TUEId, .AssetId, .EntitlemntUomId (set at order time by the Order Handler's AccountPlan step)
  • Bill, Balance, TransactionSummary, Plan, Pricing, AccountPlan — read by the Python half
